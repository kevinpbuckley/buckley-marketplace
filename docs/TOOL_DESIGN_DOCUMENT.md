# XM Cloud Solution Review - Tool Design Document

## Overview

This document maps the XM Cloud Solution Review Checklist items (primarily Section 5: Sitecore Architecture) to the available Marketplace SDK APIs. The goal is to identify which review items can be automated using read-only SDK tools to assist reviewers.

**Scope:** Read-only tools using the client SDK only. No tools will edit or create data.

---

## Available SDK APIs (Read-Only)

### Content Item APIs (`xmc.agent.content*`)

These APIs allow reading items and their fields directly:

| API | Description | Returns |
|-----|-------------|---------|
| `contentGetContentItemById` | Get content item by ID | `ContentItemResponse` with fields, template, workflow, children |
| `contentGetContentItemByPath` | Get content item by path | `ContentItemResponse` |
| `contentListAvailableInsertoptions` | Get insert options for an item | `InsertOptionModel[]` |

#### ContentItemResponse Properties
```typescript
{
  itemId: string;
  name: string;
  path: string;
  template: { templateId: string; name: string };
  fields?: { [key: string]: unknown };  // ✅ All field values!
  children?: { [key: string]: ContentItemResponse[] };
  workflow?: WorkflowModel;
  version?: number;
  created_at?: string;
  updated_at?: string;
}
```

### Page Template APIs (`xmc.agent.pagesGetPageTemplateById`)

| API | Description | Returns |
|-----|-------------|---------|
| `pagesGetPageTemplateById` | Get page template with fields | `PageTemplateResponse` |

#### PageTemplateResponse Properties
```typescript
{
  templateId: string;
  name: string;
  fields: PageTemplateFieldModel[];  // ✅ Field definitions with types!
}
```

#### PageTemplateFieldModel Properties
```typescript
{
  name: string;
  type: string;        // ✅ Field type (e.g., "Treelist", "Rich Text", etc.)
  validation: boolean;
}
```

### Component APIs (`xmc.agent.components*`)

| API | Description | Returns |
|-----|-------------|---------|
| `componentsListComponents` | List all components for a site | `ComponentsResponse` |
| `componentsGetComponent` | Get component details | `ComponentResponse` |
| `componentsSearchComponentDatasources` | Search datasources | `SearchResponse` |

#### ComponentResponse Properties
```typescript
{
  id: string;
  name: string;
  datasourceTemplateId: string;
  datasourceTemplatePath: string;
  datasourceLocations: string[];
  datasourceFields: DatasourceFieldNode[];  // ✅ Field definitions!
  datasourceAutoGenerated: boolean;
  datasourceRequired: boolean;
  hasDynamicPlaceholder?: boolean;
}
```

#### DatasourceFieldNode Properties
```typescript
{
  name: string;
  type: string;        // ✅ Field type!
  validation: string;
}
```

## Section 5: Sitecore Architecture - Tool Mapping

### 5.2 Data Templates

| Review Item | Can Automate? | SDK API(s) | Tool Name | Notes |
|------------|---------------|------------|-----------|-------|
| **Naming conventions are consistent** | ✅ Yes | `contentGetContentItemByPath`, `componentsListComponents` | `analyzeTemplateNaming` | Can get all templates/components and check naming patterns |
| **Folder structure is well organized** | ✅ Yes | `contentGetContentItemById/ByPath` | `analyzeTemplateStructure` | Can traverse template folders via path |
| **Minimize the number of templates** | ✅ Yes | `componentsListComponents`, `pagesGetPageTemplateById` | `countTemplates` | Can count all components and page templates |
| **Make good use of inheritance** | ⚠️ Partial | `contentGetContentItemById` | `analyzeTemplateInheritance` | Template info available but base templates may require traversal |
| **No cyclical template inheritance** | ⚠️ Partial | `contentGetContentItemById` | `checkCyclicalInheritance` | Would need to traverse template hierarchy |
| **Avoid duplicate field names** | ✅ Yes | `pagesGetPageTemplateById`, `componentsGetComponent` | `checkDuplicateFields` | Field definitions with names available |
| **Assign icons to templates** | ⚠️ Partial | `contentGetContentItemById` | `checkTemplateIcons` | May be in fields if standard template fields exposed |
| **Standard Values are utilized** | ✅ Yes | `contentGetContentItemById` | `checkStandardValues` | Can get Standard Values item as child of template |
| **Presentation details on Standard Values** | ✅ Yes | `contentGetContentItemById` | `checkPresentationDetails` | Fields include presentation/layout fields |
| **Insert options configured** | ✅ Yes | `contentListAvailableInsertoptions` | `listInsertOptions` | Direct API for this |
| **Insert from template secured** | ❌ No | - | - | Security not exposed |
| **Use tokens ($name, etc.)** | ✅ Yes | `contentGetContentItemById` | `checkTokenUsage` | Can read Standard Values fields for token patterns |
| **Custom tokens are meaningful** | ✅ Yes | `contentGetContentItemById` | `analyzeCustomTokens` | Can read token values from Standard Values |
| **Branch Templates used appropriately** | ✅ Yes | `contentGetContentItemByPath` | `listBranchTemplates` | Can query `/sitecore/templates/Branches/*` |
| **Define source for image fields** | ✅ Yes | `componentsGetComponent`, `pagesGetPageTemplateById` | `checkFieldSources` | DatasourceFieldNode has field definitions |
| **Define source for Multi Select Fields** | ✅ Yes | `componentsGetComponent`, `pagesGetPageTemplateById` | `checkFieldSources` | Field type and validation available |
| **Rich Text Editor profiles configured** | ⚠️ Partial | `contentGetContentItemById` | `checkRTEProfiles` | Would need to read RTE profile items |
| **Utilize data sources instead of fields** | ✅ Yes | `componentsGetComponent` | `analyzeComponentDatasources` | `datasourceRequired`, `datasourceFields` exposed |
| **Use TreelistEx instead of Treelist** | ✅ Yes | `pagesGetPageTemplateById`, `componentsGetComponent` | `checkFieldTypes` | Field `type` property available! |

## Tools NOT Possible with Current SDK

The following review items **cannot** be automated with the current SDK:

### Security Review
- Role-based access configuration
- Security inheritance
- Publishing restrictions
- Insert from template security

### Workflow Action Details
- Email notification configuration
- Workflow action scripts/commands

```typescript
import { z } from 'zod';
import { tool } from 'ai';
import type { ToolDefinition, ToolExecutor } from './types';

export const definition: ToolDefinition = {
  name: 'toolName',
  description: 'What the tool does and when to use it',
  category: 'XMC SDK',
  inputSchema: z.object({
    // Input parameters
  }),
  examples: [...],
  clientSide: true,
};

export const aiTool = tool({
  description: definition.description,
  inputSchema: definition.inputSchema,
});

export const execute: ToolExecutor = async (input, context) => {
  // Implementation using context.client.query()
};
```
